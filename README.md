# polka_ai
Сервис пакетной генерации карточек товаров для маркетплейса

# Требование к сервису
- Качество: не меньше 80% карточек проходят автоматическую валидацию формата.
- Скорость: бенчмарк-набор из 300 карточек обрабатывается за один сеанс ВМ; целевая скорость — весь набор не дольше восьми минут на одной T4.
- Стоимость: при плановом объёме 50 000 карточек в месяц стоимость обработки 1000 карточек не превышает 25₽. Дополнительно: определить, при каком объёме выгоднее API.
- Длина входа: не больше 1500 токенов на карточку, считать токенайзером модели. Товары, где отзывов больше, требуют стратегии сокращения.

# Пример валидной карточки:
```json
{
  "product_id": "P-1001",
  "description": "Компактные внутриканальные наушники с Bluetooth 5.3 и защитой IPX4. Держат заряд до 24 часов и надёжно сидят при активном движении. Подойдут для спорта и повседневного использования.",
  "pros": ["Чистый звук", "Удобная посадка", "Долгое время работы"],
  "cons": ["Быстро разряжаются на морозе"],
  "tags": ["наушники", "беспроводные", "спорт", "IPX4", "Bluetooth 5.3"]
}
```
# Карточка валидна, если выполнены все правила:

| Правило | Зачем |
| :--- | :--- |
| Это JSON-объект, без текста вокруг | Витрина парсит JSON; лишний текст или Markdown-обёртка ломают парсинг |
| Есть все пять полей: product_id, description, pros, cons, tags | Каждому полю в шаблоне соответствует свой блок |
| product_id совпадает с товаром на входе | Иначе карточка попадёт не к тому товару |
| description — строка длиной 120–700 символов | Не должно быть ни пустого описания, ни «простыни» на экран |
| description — два–пять предложений | Формат карточки: короткий связный абзац, а не одно слово и не десять предложений |
| pros — список из двух–пяти непустых строк | Блок «плюсы» показывает несколько пунктов |
| cons — список из одной–трёх непустых строк | Блок «минусы» показывает один–три пункта |
| tags — список из трёх–восьми непустых строк | Теги для поиска, нужно несколько |

Ожидаемый артефакт: таблица throughput/latency по уровням concurrency, выбранная точка, скорость в рамках требования к сервису.

Concurrency 32 здесь лучшая точка из измеренных. Оценка на 300 карточек — **186 секунд**, это **3.1 минуты**, порог 8 минут выполнен с запасом. Ошибок нет ни на одном уровне.

Скорость росла на каждом шаге, плато так и не наступило:

| concurrency | карточек/с | во сколько раз быстрее предыдущего | latency | на 300 |

## Этап 7. Стоимость и решение
Ожидаемый артефакт: расчёт цены обоими способами, объём перехода на API, итоговая рекомендация.

Свой сервер на полном бенчмарке стоит **7.40 ₽ за 1000 карточек**, API — **28.20 ₽**. На плановых 50 000 карточках в месяц свой сервер дешевле и укладывается в лимит 25 ₽, если виртуальную машину включать только на прогон.

**Свой сервер.** 300 карточек `benchmark.jsonl` при concurrency 32 заняли 123 секунды, аренда GPU — 65 ₽ в час.

\[
(123 / 3600 \times 65) / 300 \times 1000 = 7.40\text{ ₽ за 1000}
\]

Прогон стоит 2.22 ₽. На 50 000 карточек это 5.7 часа и **370 ₽ в месяц**.

**API.** Токены взяты из прогона OpenRouter, 20 карточек: 9716 входных и 6161 выходной. Токены локальной модели сюда не подставляются.

\[
(9716 \times 20 + 6161 \times 60) / 1\,000\,000 / 20 \times 1000 = 28.20\text{ ₽ за 1000}
\]

На 50 000 карточек это **1410 ₽ в месяц**.

**Когда выгоднее API.** GPU оплачивается и в простое. Если машина арендована весь месяц (30 суток, 720 часов, 46 800 ₽) и почти не считает, цена своего сервера на малом объёме выше API. Равенство:

\[
46\,800 / (28.20 / 1000) \approx 1.66\text{ млн карточек в месяц}
\]

Ниже этого объёма круглосуточная ВМ дороже API. Выше — фиксированная аренда уже дешевле токенов. На 50 000 карточках круглосуточная T4 даёт 936 ₽ за 1000, API — 28.20 ₽.

**Решение.** На плановом объёме поднимаем ВМ под пакет и выключаем после прогона. Получается 7.40 ₽ за 1000 при лимите 25 ₽, и это дешевле API. Качество локального прогона на 300 карточках — 279 из 300, порог 80% выполнен. API на 20 карточках дал 20 из 20, но за те же деньги на этом объёме он не окупается.
