# polka_ai
Сервис пакетной генерации карточек товаров для маркетплейса

# Требование к сервису
- Качество: не меньше 80% карточек проходят автоматическую валидацию формата.
- Скорость: бенчмарк-набор из 300 карточек обрабатывается за один сеанс ВМ; целевая скорость — весь набор не дольше восьми минут на одной T4.
- Стоимость: при плановом объёме 50 000 карточек в месяц стоимость обработки 1000 карточек не превышает 25₽. Дополнительно: определить, при каком объёме выгоднее API.
- Длина входа: не больше 1500 токенов на карточку, считать токенайзером модели. Товары, где отзывов больше, требуют стратегии сокращения.


# Описание датасета

```json
  "reviews": ["Звук чистый, бас глубокий, за свои деньги отлично", "На морозе быстро садятся, зимой неудобно"]
}
```
# Пример валидной карточки:
```json
{
  "product_id": "P-1001",
  "description": "Компактные внутриканальные наушники с Bluetooth 5.3 и защитой IPX4. Держат заряд до 24 часов и надёжно сидят при активном движении. Подойдут для спорта и повседневного использования.",
  "pros": ["Чистый звук", "Удобная посадка", "Долгое время работы"],
  "cons": ["Быстро разряжаются на морозе"],
  "tags": ["наушники", "беспроводные", "спорт", "IPX4", "Bluetooth 5.3"]
}
```
# Карточка валидна, если выполнены все правила:

| Правило | Зачем |
| :--- | :--- |
| Это JSON-объект, без текста вокруг | Витрина парсит JSON; лишний текст или Markdown-обёртка ломают парсинг |
| Есть все пять полей: product_id, description, pros, cons, tags | Каждому полю в шаблоне соответствует свой блок |
| product_id совпадает с товаром на входе | Иначе карточка попадёт не к тому товару |
| description — строка длиной 120–700 символов | Не должно быть ни пустого описания, ни «простыни» на экран |
| description — два–пять предложений | Формат карточки: короткий связный абзац, а не одно слово и не десять предложений |
| pros — список из двух–пяти непустых строк | Блок «плюсы» показывает несколько пунктов |
| cons — список из одной–трёх непустых строк | Блок «минусы» показывает один–три пункта |
| tags — список из трёх–восьми непустых строк | Теги для поиска, нужно несколько |


# Отчёт по проекту

## Финальный конфиг
- Модель `Qwen/Qwen2.5-1.5B-Instruct`, dtype `half` (float16). Сервер: `vllm serve` с `--max-model-len 4096`, `--gpu-memory-utilization 0.85`, `--enforce-eager`, порт 8000, GPU Tesla T4.
- Генерация: `temperature 0.0`, `top_p 1.0`, `top_k 20`, `repetition_penalty 1.2`, `max_tokens 500`. Формат держит `structured_outputs` по JSON-схеме. Пакет на бенчмарке идёт при concurrency 32.
- Длинный вход: повторы отзывов схлопываются по смыслу, из дублей остаётся самая короткая фраза. Если уникальный набор всё ещё длиннее 1500 токенов на весь промпт, берётся равномерная выборка с первым и последним отзывом. На `dev.jsonl` хватило схлопывания: самый длинный промпт после него — 579 токенов (`P-0033`), у `P-0002` 173 отзыва и 4040 токенов сжались до 14 отзывов и 557 токенов.
- При браке формата карточка не переспрашивается: один запрос, `avg_attempts` 1. При температуре 0 повтор даёт тот же текст, а оставшийся брак — число предложений, его схема не держит.

## Сравнение с моделью через API
Один промпт, первые 20 товаров `dev.jsonl`. API: `nvidia/nemotron-3.5-lightning:free`. Цена своего сервера здесь — по времени GPU на полном бенчмарке, цена API — по токенам этого прогона. Так записано в `outputs/report.json`.

| Что сравниваем | Локальная модель на vLLM | Модель через API |
| --- | --- | --- |
| Доля валидных карточек | 18/20, 90% | 20/20, 100% |
| Токенов на карточку, вход/выход | 488 / 286 | 486 / 308 |
| Время на карточку | 11.37 с | 3.60 с |
| Стоимость 1000 карточек | 7.40 ₽ | 28.20 ₽ |

Время API включает сеть. На этих 20 карточках запрос всё равно короче: 3.60 с против 11.37 с.

По пути отвалилась `recursive/flint-v1.0:free`: провайдер отвечал 503, upstream не было. 429 ждёт с паузой до окна лимита, 5xx повторяется ограниченно, 400 снимает непринятый параметр и шлёт запрос заново. Один отказ не останавливает пачку. У Nemotron скрытые рассуждения съедали `max_tokens` и оставляли пустой ответ; в запрос добавлено `reasoning.enabled: false`, текст промпта тот же.

Качество на этих 20 карточках выше у API, 20 из 20 против 18 из 20. Дешевле свой сервер: 7.40 ₽ против 28.20 ₽ за 1000. На бенчмарке из 300 карточек локальная модель даёт 279 валидных, порог 80% выполнен.

## Замеры
- доля валидных карточек: 279 из 300, valid_rate 0.93. Брак: предложений 20, Не JSON 1
- скорость: concurrency 32, throughput 2.439 карточки/с, средняя задержка 12.37 с
- время на весь бенчмарк: 123.0 с
- стоимость: на своём сервере 7.40 ₽/1000 из полного прогона, через API 28.20 ₽/1000 из прогона этапа 6 (9716 входных и 6161 выходной токен на 20 карточках)

## Длинный вход
Отбор уникальных отзывов, не обрезка начала списка и не второй запрос к модели. Зачины «Коротко:», «Пользуюсь месяц.» и остальные из того же списка на смысл не влияют, из дублей остаётся короткая фраза. Лимит 1500 токенов считается токенайзером Qwen на весь промпт. Равномерная выборка — запасной шаг, на `dev.jsonl` она не понадобилась. `P-0002`: 173 отзыва → 14, 4040 → 557 токенов. Минусы после схлопывания остаются.

## Оптимизации
Сервер запущен с `--dtype half`, это float16. На T4 этого хватило для выбранной скорости: 300 карточек за 123.0 с. INT4 отдельно не замерялся.

## Стоимость и решение
Свой сервер, 300 карточек за 123.0 с при 65 ₽/час: `(123 / 3600 × 65) / 300 × 1000 = 7.40` ₽ за 1000. На 50 000 карточек это 5.7 часа и 370 ₽ в месяц.

API, 20 карточек, 9716 входных и 6161 выходной токен: `(9716 × 20 + 6161 × 60) / 1 000 000 / 20 × 1000 = 28.20` ₽ за 1000. На 50 000 карточек это 1410 ₽ в месяц.

Если GPU арендован весь месяц и простаивает (720 часов, 46 800 ₽), API дешевле, пока карточек меньше примерно 1.66 млн в месяц. На плановых 50 000 круглосуточная T4 стоила бы 936 ₽ за 1000.

Итог: на плановом объёме поднимать ВМ под пакет и выключать. 7.40 ₽ за 1000 при лимите 25 ₽, и это дешевле API. Качество 279 из 300.

## Этап 4. Обработать длинный вход
Стратегия — отбор уникальных отзывов. У популярных товаров одни и те же фразы повторяются с зачинами вроде «Коротко:» и «Пользуюсь месяц.». 
Перед запросом происходит следующее:

- одинаковые по смыслу отзывы схлопываются, остаётся самая короткая формулировка;
- токенайзер `Qwen2.5-1.5B` считает весь промпт;
- если уникальных отзывов всё ещё больше 1500 токенов, остаётся равномерная выборка по списку, с первым и последним отзывом.

На `dev.jsonl` после этого все 40 карточек укладываются в лимит. Самый длинный вход — 579 токенов (`P-0033`) вместо прежних 4426 у `P-0039`, из-за которых запрос не влезал в контекст.

На примере: У смартфона Xilo M20 все 173 отзыва — это 14 фраз. Меняется только зачин: «Коротко:», «Пользуюсь месяц.», «Купил на замену старому.» и так далее.

Самая частая фраза повторяется 24 раза: «В руке лежит удобно, не скользит». Дальше по убыванию:

| Раз | Фраза |
| ---: | --- |

| 22 | батарея держит полтора дня без подзарядки |
| 19 | звонки чистые, собеседника слышно хорошо |
| 18 | работает шустро, приложения не тормозят |
| 18 | камера снимает достойно даже вечером |
| 17 | быстро заряжается, за час почти полный |
| 13 | экран яркий, на солнце всё видно |
| 10 | предустановлено много ненужных приложений |

| 6 | греется при играх и долгой съёмке |

В запрос уходит по одной, самой короткой копии каждой фразы. Минусы при этом не пропадают: греется, мылит, тихий динамик и быстрый разряд остаются. 4040 токенов были в основном этими повторами, поэтому после отбора осталось 557.


## Этап 5. Пакетная обработка и батчинг
Concurrency 32 здесь лучшая точка из измеренных. Оценка на 300 карточек — **186 секунд**, это **3.1 минуты**, порог 8 минут выполнен с запасом. Ошибок нет ни на одном уровне.

Скорость росла на каждом шаге, плато так и не наступило:

| concurrency | карточек/с | во сколько раз быстрее предыдущего | latency | на 300 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0.10 | — | 9.81 с | 49 мин |
| 4 | 0.36 | ×3.6 | 10.58 с | 14.0 мин |
| 16 | 1.05 | ×2.9 | 12.40 с | 4.8 мин |
| 32 | 1.62 | ×1.5 | 12.25 с | 3.1 мин |

От 16 к 32 скорость выросла на 54%, это больше порога 10%. Задержка при этом не выросла: 12.25 с против 12.40 с. Карточка ждёт почти столько же, а сервис успевает больше за счёт параллельной очереди.

**Качество выше у API:** все 20 карточек прошли проверку. Локальная модель на этом наборе даёт 18 из 20.

**Дешевле локальная модель,** но разница маленькая: 26.94 ₽ против 28.20 ₽ за 1000 карточек. Вход почти одинаковый, около 490 токенов. API пишет чуть длиннее, 308 выходных токенов против 286, а выход в прайсе втрое дороже входа (60 ₽ и 20 ₽ за миллион).


## Этап 7. Стоимость и решение
Свой сервер на полном бенчмарке стоит **7.40 ₽ за 1000 карточек**, API — **28.20 ₽**. На плановых 50 000 карточках в месяц свой сервер дешевле и укладывается в лимит 25 ₽, если виртуальную машину включать только на прогон.

**Свой сервер.** 300 карточек `benchmark.jsonl` при concurrency 32 заняли 123 секунды, аренда GPU — 65 ₽ в час.

`(123 / 3600 × 65) / 300 × 1000 = 7.40 ₽ за 1000`

Прогон стоит 2.22 ₽. На 50 000 карточек это 5.7 часа и **370 ₽ в месяц**.

**API.** Токены взяты из прогона OpenRouter, 20 карточек: 9716 входных и 6161 выходной. Токены локальной модели сюда не подставляются.

`(9716 × 20 + 6161 × 60) / 1 000 000 / 20 × 1000 = 28.20 ₽ за 1000`

На 50 000 карточек это **1410 ₽ в месяц**.

**Когда выгоднее API.** GPU оплачивается и в простое. Если машина арендована весь месяц (30 суток, 720 часов, 46 800 ₽) и почти не считает, цена своего сервера на малом объёме выше API. Равенство:

`46 800 / (28.20 / 1000) ≈ 1.66 млн карточек в месяц`

Ниже этого объёма круглосуточная ВМ дороже API. Выше — фиксированная аренда уже дешевле токенов. На 50 000 карточках круглосуточная T4 даёт 936 ₽ за 1000, API — 28.20 ₽.

**Решение.** На плановом объёме поднимаем ВМ под пакет и выключаем после прогона. Получается 7.40 ₽ за 1000 при лимите 25 ₽, и это дешевле API. Качество локального прогона на 300 карточках — 279 из 300, порог 80% выполнен. API на 20 карточках дал 20 из 20, но за те же деньги на этом объёме он не окупается.


Работа сделана в двух местах.

`prompt_test.ipynb` — локальный vLLM в Colab: промпт, валидация, параметры, параллельный прогон и бенчмарк на 300 карточках. `compare_api.py` — тот же промпт через OpenRouter: загрузка карточек, сокращение отзывов и проверка формата лежат в этом файле. Итог, который смотрят без запуска, лежит в `outputs/report.json` и в README.
