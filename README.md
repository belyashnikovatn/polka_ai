# polka_ai
Сервис пакетной генерации карточек товаров для маркетплейса

# Требование к сервису
- Качество: не меньше 80% карточек проходят автоматическую валидацию формата.
- Скорость: бенчмарк-набор из 300 карточек обрабатывается за один сеанс ВМ; целевая скорость — весь набор не дольше восьми минут на одной T4.
- Стоимость: при плановом объёме 50 000 карточек в месяц стоимость обработки 1000 карточек не превышает 25₽. Дополнительно: определить, при каком объёме выгоднее API.
- Длина входа: не больше 1500 токенов на карточку, считать токенайзером модели. Товары, где отзывов больше, требуют стратегии сокращения.

# Пример валидной карточки:
```json
{
  "product_id": "P-1001",
  "description": "Компактные внутриканальные наушники с Bluetooth 5.3 и защитой IPX4. Держат заряд до 24 часов и надёжно сидят при активном движении. Подойдут для спорта и повседневного использования.",
  "pros": ["Чистый звук", "Удобная посадка", "Долгое время работы"],
  "cons": ["Быстро разряжаются на морозе"],
  "tags": ["наушники", "беспроводные", "спорт", "IPX4", "Bluetooth 5.3"]
}
```
# Карточка валидна, если выполнены все правила:

| Правило | Зачем |
| :--- | :--- |
| Это JSON-объект, без текста вокруг | Витрина парсит JSON; лишний текст или Markdown-обёртка ломают парсинг |
| Есть все пять полей: product_id, description, pros, cons, tags | Каждому полю в шаблоне соответствует свой блок |
| product_id совпадает с товаром на входе | Иначе карточка попадёт не к тому товару |
| description — строка длиной 120–700 символов | Не должно быть ни пустого описания, ни «простыни» на экран |
| description — два–пять предложений | Формат карточки: короткий связный абзац, а не одно слово и не десять предложений |
| pros — список из двух–пяти непустых строк | Блок «плюсы» показывает несколько пунктов |
| cons — список из одной–трёх непустых строк | Блок «минусы» показывает один–три пункта |
| tags — список из трёх–восьми непустых строк | Теги для поиска, нужно несколько |


# Отчёт по проекту

## Финальный конфиг
- модель, dtype, параметры vLLM
- стратегия длинного входа
- сколько повторов при браке формата и почему

## Параметры генерации
- таблица экспериментов и выбранные значения
- что изменилось при подборе: доля валидных, длина описания, выходные токены

## Сравнение с моделью через API
- таблица: качество, токены, скорость, стоимость
- какие ошибки API встретились и как обработаны
- вывод: что дешевле, что качественнее на этой задаче

## Замеры
- доля валидных карточек: ... , разбивка брака по причинам
- скорость: таблица throughput/latency по concurrency, выбранная точка
- время на весь бенчмарк: ...
- стоимость: на своём сервере ... ₽/1000 из полного прогона, через API ... ₽/1000 из прогона этапа 6

## Длинный вход
- какую стратегию выбрал и почему

## Оптимизации
- выбор точности: float16 или INT4, с обоснованием (замер по желанию)

## Стоимость и решение
- расчёт обоими способами
- при каком объёме выгоднее API
- итог: свой сервер или API и почему
